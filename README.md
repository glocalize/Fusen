# Fusen! 📌

Webサイトレビューツール。レビューしたいサイトのURLを登録すると「キャンバス」になり、ページの上に直接ピン留めコメントを貼って、承認/修正依頼までを一気通貫で行えます。

> **これは何のためのツールか:** 自分（またはチーム）が**権利を持っている、もしくはレビューの許可を得ているサイト**——とくにステージング環境やプロトタイプ——にコメントを付けてレビューするための、自己ホスト型ツールです。第三者のサイトを無断で取り込んで利用することは想定していません。詳しくは下の「利用上の注意・免責」を参照してください。

## 技術構成

- **Cloudflare Workers**（[Hono](https://hono.dev/) ルーティング）で動作するサーバーアプリ
- データは **Cloudflare D1**（SQLite）に保存。スキーマは `migrations/`、データ層は `lib/db-d1.js`
- フロントは素の HTML/CSS/JS（`public/`、Workers Assets で配信）
- プロキシ: 対象サイトのHTMLを取得し、注釈オーバーレイ（`public/fusen-overlay.js`）を注入して `/p/<キャンバスID>/…` 配下にミラー配信

> 旧 Express + JSONストア版（`server.js` / `lib/*.js`）は Workers 版へ移行済みのため削除しました。過去のコードが必要な場合は git 履歴を参照してください。

## セットアップ（ローカル開発）

Node.js 18以上が必要です。

```bash
cd fusen
npm install

# 認証の署名鍵をローカル用に設定(下記「必須の設定」を参照)
cp .dev.vars.example .dev.vars   # SESSION_SECRET を任意のランダム文字列に書き換える

# ローカル D1 の作成とシード
npm run cf:seed:gen              # data/db.json から seed.sql を生成
npm run cf:migrate:local
npm run cf:seed:local

npm run dev                      # wrangler dev で起動
```

ブラウザで表示された URL を開き、名前を入れてログインしてください（パスワード不要）。

## 必須の設定: `SESSION_SECRET`

認証クッキーは `SESSION_SECRET` で **HMAC 署名** します（クッキー偽造を防ぐため）。**これが未設定だとログインは 500 で失敗します。**

- ローカル: `.dev.vars` に `SESSION_SECRET="十分に長いランダム文字列"` を設定
- 本番（デプロイ前に必須）:

  ```bash
  npx wrangler secret put SESSION_SECRET
  ```

生成例: `openssl rand -base64 32`

## デプロイ

`account_id` はリポジトリに含めていないので、環境変数で渡します（未設定なら wrangler が対話的に選択）。

```bash
export CLOUDFLARE_ACCOUNT_ID=xxxxxxxx   # 自分のCloudflare account_id

npm run cf:migrate:remote        # 本番 D1 にマイグレーション
npm run cf:seed:remote           # 初回のみ(既存データがある場合は不要)
npm run cf:deploy                # wrangler deploy
```

Basic認証付きステージング/SPA を表示する場合は、対象ホスト等をシークレットで設定します（内部URLを公開設定に残さないため。シークレットは deploy で消えず永続します）。

```bash
npx wrangler secret put PROXY_BASIC_AUTH        # 値は "ユーザー名:パスワード"
npx wrangler secret put PROXY_BASIC_AUTH_HOSTS  # 対象ホスト(カンマ区切り)
npx wrangler secret put PROXY_SPA_HOSTS         # 対象ホスト(カンマ区切り)
```

> 公開する場合は **Cloudflare Access**（社内メンバーのみ許可）を併用してください。名前ログインはなりすまし（他人の名前を騙る）を防げないため、アクセス境界は Access 側で担保します。

## 使い方

1. **+ 新しいキャンバス** でレビューしたいサイトのURLを登録
2. カードをクリックするとサイトがレビュー画面で開く
3. 下部ツールバーで **コメント** モードに切替 → ページ上をクリック → コメントを書いて貼る
4. **見る** モードに戻すとサイトを普通に回遊できる（コメントはページごとに保存）
5. **共有** でゲスト用リンクをコピー（招待された1キャンバスにのみアクセス可能）
6. コメントスレッドの **Issue化** で、そのスレッドを Issue 用のテキスト（タイトル / Markdown 本文）に整形してコピー。画面全体のスクショも「画像をコピー」/「PNG保存」で添付できる（Issue管理ツールとは連携せず、貼り付けはユーザーが手動で行う「コピペ運用」）
7. **レビュー完了** で「承認」または「修正依頼」を送信

## デバッグ画面（動的UIのピン挙動確認）

モーダル・タブなどの**動的UIに対するピンの追従挙動**を、外部サイトを登録せずに確認できる自己完結のサンプル画面を用意しています。**追加設定は不要**です（API はページ内でスタブ化しており DB・ログインに触れません。`SESSION_SECRET` 未設定でも開けます）。

```bash
npm run dev          # wrangler dev で起動(既定ポート 8787)
```

- ローカル: ブラウザで **`http://localhost:8787/debug`** を開く
- デプロイ済み環境: **`https://<あなたのFusenドメイン>/debug`**（Cloudflare Access の内側でチーム誰でも到達可能）

画面右上のパネルで「モーダルを開く／閉じる／DOM変化」を操作できます。確認手順:

1. 下部ツールバーを **コメント** モードに切替
2. **モーダルを開く** → モーダル内の要素をクリックして Pin を打つ
3. **見る** モードに戻して **閉じる**（×／背景クリックでも可）→ ピンが座標に浮かず隠れることを確認（サイドバーには `⚠ 非表示` と表示）
4. **DOM変化** → 再度 **モーダルを開く** → 安定属性(`data-testid`等)ありは**再アンカー**、なしは隠れたまま

### 自動テスト（VRT / アンカー回帰）

同じサンプルをヘッドレス Chrome で駆動し、ピンの不変条件（スクロール追従／モーダル表示中は要素に乗る／閉じたら浮かず隠れる／再オープンで再アンカー）を検証し、スクショを保存します。

```bash
npm run test:anchor   # test/anchor/__screenshots__/ にスクショ出力
```

> macOS の Google Chrome を使用（依存追加なし）。Chrome に依存するため CI の `npm test` には含めていません（手元での回帰確認用）。

## セキュリティ

`docs/security-audit.md` の監査を受けて、以下を実装しています（詳細は各コミット `[I1]`〜`[I9]`）。

- **認証**: 名前ログインの UX は維持しつつ、identity を `SESSION_SECRET` による HMAC 署名クッキーで保持。偽造・改変クッキーは拒否。`HttpOnly` / `SameSite=Lax` / `Secure`(https)
- **SSRF**: 取得先URLを共通ヘルパー `lib/safefetch.js` で検証（内部IP・ループバック・リンクローカル・`localhost`・`*.internal`・数値IPを拒否）。リダイレクトは手動で各ホップを再検証
- **認可**: キャンバス単位のアクセス制御。ゲストは招待された1キャンバスのみ（一覧列挙・他キャンバス閲覧は不可）。コメント削除は投稿者本人のみ
- **CSRF**: 状態変更API（POST/PATCH/DELETE）は同一オリジンのみ許可
- **XSS**: 注入する `window.__FUSEN__` は `<` と U+2028/U+2029 をエスケープ。CSP は全除去せず注入分のみ nonce で許可
- **その他**: 共有トークンは CSPRNG 生成、ログイン後遷移先(`next`)は同一オリジン相対のみ、中継ボディにサイズ上限

### 既知の限界（重要）

- **同一オリジンでの未信頼JS**: プロキシは対象サイトを Fusen 自身のオリジンで配信します。短期策（HttpOnly / Origin検証 / CSP nonce）でリスクは縮小していますが、「対象サイトの未信頼JSが同一オリジンで動く」という根本リスクは残ります。完全な解消には sandbox iframe による別オリジン隔離が必要で、これはバックログ（`I-FUTURE`）です。**信頼できないサイトを取り込む用途には使わないでください。**
- **アクセス境界は Cloudflare Access（設計上の前提）**: 本ツールは **Cloudflare Access で社内メンバー（許可ドメイン）のみがアプリに到達できる**ことを前提に設計しています。アプリ内の名前ログインは identity 表示用で、`guest`/`member` の区別は UX ロールであり、外部からの侵入を防ぐ境界ではありません（Access を通れる時点で全員が正当なメンバー）。そのため次は既知の前提です: ①名前のみログインなので他人の名前を騙るなりすましは防げない、②`guest` フラグはクライアント任意なので Access の内側では member 相当に振る舞える。**この前提が崩れる運用（Access を外す／外部ゲストに共有リンクを配る）は想定していません。** その場合はメンバーログインを Access のID(`Cf-Access-Authenticated-User-Email`)でサーバー側判定する等の追加対策が必要です。
- **レート制限なし**: Workers でのレート制限は KV / Durable Objects が必要なため未実装（バックログ）。login / check-url / 共有入口の総当たり対策は今後の課題です。
